Test your iOS app with Claude Code or Codex

Last updated: 16 November 2026

AI-OS is a free Mac app and a local MCP server. Your AI agent sends the steps of a test; AI-OS runs them on an iOS simulator or a real iPhone, looks at the screen before each step, and sends back what happened. This guide goes from the download to a test of your own app.

What you need

  • A Mac with Apple silicon and macOS 26 (Tahoe) or later.
  • Xcode 26 or later. Setup opens the App Store if it is missing.
  • Claude Code, Claude Desktop, Codex or another MCP client.
  • A simulator build of your app. For a real iPhone, read Test on a real iPhone.

1. Install AI-OS

  1. Download AI-OS and open the zip.
  2. Open AI-OS.app. The first time, macOS stops it: open System Settings, Privacy & Security, and click Open Anyway.
  3. Click Set up. It installs only what your Mac is missing (iOS for simulators, the simulator driver and simslim) and shows each step.

2. Connect your AI agent

Setup connects AI-OS to Claude Code, Claude Desktop and Codex, if you have them. To connect one later, open the AI-OS app, then Settings, AI connection:

  • Claude Code: Register in Claude Code, then open a new Claude Code session.
  • Claude Desktop: Add to Claude Desktop, then restart Claude Desktop.
  • Codex: Register in Codex, then open a new Codex session.

The same from Terminal:

~/ai-os/bin/aios connect --claude-code
~/ai-os/bin/aios connect --claude-desktop
~/ai-os/bin/aios connect --codex

For any other MCP client, this shows what is connected and the server settings to put in that client's MCP config:

~/ai-os/bin/aios connect

The first time an AI session uses each AI-OS tool, Claude Code asks you to allow it, and the agent waits for your click. To allow every AI-OS tool at once, add this to ~/.claude/settings.json:

{"permissions": {"allow": ["mcp__ai-os"]}}

3. Run a first test

Paste this into your agent:

Use AI-OS: turn on an iPhone simulator, open the Settings app and tell me what its first screen shows.

The agent turns on a simulator, opens Settings and reads the screen as text.

4. Test your own app

On a simulator, AI-OS installs a .app built for the iOS Simulator, or a .zip holding one.

  • Xcode: build for an iOS Simulator destination.
  • Flutter: flutter build ios --simulator
  • An .ipa, a TestFlight link or a build for real iPhones cannot run on a simulator.

Choose a builds folder in the AI-OS app (Settings, Logins) and ask for a build by its name, or give the agent its path. Then describe the test in plain words, for example:

Use AI-OS: install MyApp.app clean on an iPhone simulator, log in with the test account and the password saved as APP_PASSWORD, and check that the Home screen shows Welcome.

What a test looks like

The agent sends every step of a test in one call. AI-OS reads the screen before each step, waits until it stops moving, and checks the result:

[{"tap": "Log in"},
 {"fill": {"field": "Email Address", "text": "qa@example.com"}},
 {"type_secret": {"field": "Password", "key": "APP_PASSWORD"}},
 {"wait_for": "Home", "timeout": 8},
 {"assert": "Welcome"}]
  • When a step cannot go on, for example after a dialog nobody expected, AI-OS asks the agent instead of hanging, with the screen and the closest matches.
  • Passwords are typed by name. The value never reaches the AI.
  • Every AI run goes into the run history in the AI-OS app, with its steps and any screenshots. Passwords are removed.

Measured on 3 November 2026, on the same Contacts test run by Claude Code with Claude Sonnet: AI-OS passed 5 of 5 with 6 agent turns (median); the other tools needed 19 to 21. See how AI-OS compares.
